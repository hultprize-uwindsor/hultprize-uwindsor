# Attendance email templates

Executable templates live in `attEmail_()` in `google-apps-script/Attendance.gs`, with `attEventText_()` for an event in the plain-text copy and `attEventHtml_()` for the same event in the HTML. They render the **current** event record when sent, with the attendee's per-event status. Tokens are generated at send time; only hashes are stored. No email body or raw management token is persisted in the delivery table.

| Message | Subject / content |
| --- | --- |
| Confirmed attendance | “You’re registered! Hult Prize at UWindsor.” Names each confirmed event and provides its schedule, venue and calendar link. |
| Mixed confirmation / waitlist | Identifies which events are confirmed and which have only a waitlist place. A waitlisted place does not reserve a seat. |
| Management link | “Your secure attendance management link.” View registrations, add events, update support needs and cancel individual events. Link expires after 48 hours and is single use. |
| Reminder | “Reminder: [event title].” Sent approximately 24 hours before a confirmed event; includes any preparation notes. Skipped if attendance or the event is cancelled or the event has started. |
| Seat offer | “A seat is available: [event title].” Explains that attendance is not yet confirmed, gives a Windsor-time acceptance deadline and an acceptance link. Offers last up to 24 hours, capped at the event start (or event end when issued during late registration). |
| Expired offer | “Your seat offer has expired.” Explains that the person remains waitlisted without a reserved seat; asks them to contact organisers if still interested. |
| Individual cancellation | “Your event attendance has been cancelled.” Confirms cancellation for that event; other attendance can be managed separately. |
| Cancelled event | “Event cancelled: [event title].” Explains that the organiser cancelled the event and no attendance reminder will be sent. |
| Material update | “Event update: [event title].” Provides current date, local time, full venue and attendance status. Triggered by the organiser's send-update control. |
| Thank-you card | “Thank you for coming to [event title] 💌.” An HTML card (the chapter's logo at the top left, then the opening-card GIF over a short note) with a plain-text copy. Goes to everyone **checked in** at the event, registered or walk-in, at 7 PM Windsor time that day (or an hour after the event ends, if later). Attendees who ticked the optional updates box also get the next event (and who leads and opens it, when `ATT_EVENT_LEADS` names them), with a one-click sign-up or their calendar links, and the Ticket Jar raffle. Everyone else gets only the thank-you. The one-click sign-up is a single-use, 48-hour management link, shown only to consenting readers who aren't yet registered for that event. |
| Missed-you letter | “We missed you at [event title] 💌.” The same kind of email with an unfolding-letter GIF: “We’re sad you couldn’t make it.” Goes to confirmed registrations with **no check-in**, at 10 AM Windsor time the morning after. Waitlisted and cancelled registrations get nothing. It asks anyone who did come to reply so the list can be fixed. With the optional updates consent it also carries the next-event invite and the Ticket Jar; otherwise just the note. One letter per run of missed events: no second letter until they have come to something again. |

Every event block contains title, status, day/date, Windsor start/end time with timezone, full venue including floor, supplied preparation instructions, and the free refreshments note. Confirmed events include Google Calendar and Outlook (Microsoft 365) links; the confirmation/manage page also offers an ICS download for Apple Calendar and other apps. In the HTML, the status is a sentence ("You're confirmed."), because the site has no status labels, and a cancelled registration leaves out the refreshments note.

Every email above except the two follow-ups (thank-you cards and missed-you letters) includes a private management link, separate competition registration link and November 20, 2026 deadline, a reminder that each team member registers individually, and the approved Discord invite https://discord.gg/ybeQYQxcqZ by default. The optional `ATTENDANCE_DISCORD_URL` script property overrides the email invite; leave it unset to use the approved default shared with `SITE.discordUrl`. The global prize is identified as the US$1 million seed investment prize.

Delivery failures are retained and visible to organisers. Retrying a delivery does not recreate registrations. Sending is **disabled by default**. Use `ATTENDANCE_EMAIL_MODE=test` with explicit `ATTENDANCE_TEST_EMAILS` recipients in an isolated staging spreadsheet. Enable `live` only after reviewing the sender and recipient data.

## How the notices look

Every notice is sent as HTML with a plain-text copy, so the long calendar and sign-in addresses appear only in the copy, which mail apps show only when they can't show HTML. The HTML uses the same pieces as the follow-ups (`attPage_()`, `attBox_()`, `attButton_()`): the logo at the top left on the pink page, then a white card with a heading, each event in a blue box, one pink button, and the team and competition reminders in a pink box. The button is **Manage my attendance**, except in a seat offer, where it is **Accept my seat** with its deadline above it in navy, and managing attendance is a text link. The Discord invite is in the footer.

The logo loads from `ATTENDANCE_SITE_URL`, so `public/images/email/logo.png` must be live before this `Attendance.gs` is pasted, or every notice shows its alt text instead. To see a real one, register your own address at `/attend`, or ask for a link at `/attend/manage` if it is already registered. An address with no registrations gets no email.

## Thank-you cards and missed-you letters

These follow-ups are built by `attFollowUp_()` and queued by `attMaintenance_()`. Thank-you cards (`thanks`) go to every check-in at the event. Missed-you letters (`missed`) go to every `confirmed` registration with no check-in. The privacy notice says broader programme updates need the optional consent, so the next-event invite and the Ticket Jar section go only to attendees whose latest consent record has `marketingAccepted: true`. Everyone else gets the note on its own.

- **Switching them on.** Follow-ups are queued automatically only when the `ATTENDANCE_FOLLOW_UP_MODE` script property is `auto`. Without it, pasting a new `Attendance.gs` can't email anyone before you have tested. Normal sending must be enabled as well (`ATTENDANCE_EMAIL_MODE=live`).
- **Timing.** An event's day is the Windsor date it ends on, or the day before if it ends before 4 AM. Thank-you cards are queued from 7 PM Windsor time on the event's day (`ATT_THANKS_HOUR`), or an hour after the event ends if that is later. Missed-you letters are queued from 10 AM the next morning (`ATT_MISSED_HOUR`), which leaves the evening to record any check-in missed at the door. Each is queued for six hours from then (`ATT_FOLLOW_UP_WINDOW`), so a long-past event never sends. A check-in recorded after a letter is queued cancels it.
- **Repeat no-shows.** A letter is skipped if the person already has a missed-you letter for an earlier event (or one starting at the same time), sent or still being tried, and no check-in at any event from that one's start until this one's. A check-in recorded at the earlier event after its letter went out counts as coming, so a corrected door mistake ends the run. A letter that never got through counts for nothing. Events are processed in start order, so two misses on the same day get one letter. Someone registered for every workshop who stops coming gets one letter, not one per workshop.
- **Next event.** This is the next event that hasn't started and is open or full, or one the reader is already registered for (events closed to registration are skipped). If `ATT_EVENT_LEADS` in `Attendance.gs` names who leads it, and anyone who joins them to open it, the invite says so with a picture of their taped Polaroids from their partner pages, beside the words on a computer and above them on a phone, where a style in the email's head lets the words use the whole box in the mail apps that read it. Peaches Madarang-Cesario leads every workshop, and Neil Cesario joins Peaches to open Workshop 2, so its picture shows both Polaroids. To name someone else, add them there and to `LEADS` in `scripts/generate-email-art.mjs`, run `node scripts/generate-email-art.mjs leads`, and set the entry's `width` to half the new picture's width. If the reader isn't registered for it, **Save my spot** opens `/attend/manage` with a single-use, 48-hour management link and that event already ticked (`#token=…&add=<event id>`), and the email asks them not to forward it. A second tap in the same browser still opens the page while that sign-in lasts (7 days). If they are registered, they get calendar links instead. A waitlisted reader is told so, someone holding a seat offer is told until when it is held, and someone whose offer expired is asked to reply if they still want to come.
- **Ticket Jar.** `ATT_RAFFLE` names the first event that gives out tickets (`workshop-1`) and the draw (`campus-grand-finale`). Follow-ups before the first ticket event say the jar opens there. After that, readers with a check-in at the first ticket event or later are told to keep filling the jar; anyone else is told to start collecting. The finale's own follow-ups leave the raffle out. The $200 prize and Grayfel Technologies Inc. sponsorship match `/blog/the-ticket-jar`.
- **Pictures.** `public/images/email/logo.png` (the website's navbar logo, on the email's pink so it stays readable when a phone darkens the email), `thank-you-card.gif`, `missed-you-letter.gif`, `raffle-tickets.png` and the event leads' Polaroids (`peaches-madarang-cesario.png`, and `peaches-and-neil-cesario.png` for Workshop 2) load from `ATTENDANCE_SITE_URL`, so the site must be deployed before follow-ups go out. Mail apps never restart a GIF that has stopped, so both GIFs loop forever, resting four seconds on the open card or letter each time. They are drawn at 1.5x so the writing stays sharp on phones; keep each under about 1.5 MB so the email loads quickly on mobile data (the generator prints each file's size). Both envelopes are black, closed with a wax seal in the shape of the Hult Prize mark. Classic Outlook for Windows and iPhones in Low Power Mode show only the first frame: the sealed envelope. Regenerate the pictures with `node scripts/generate-email-art.mjs` (needs ffmpeg) after editing the scenes in `scripts/email-art/`. It also prints the GIFs' fingerprint: put it in `ATT_ART_VERSION` in `Attendance.gs`, which adds it to each GIF's address, because mail apps cache pictures by address. `npm run test:attendance` fails until the two match. Deploy the site and check the new pictures are live before pasting the new `Attendance.gs`, or a test email could fetch the old picture at the new address and keep it.
- **Sender picture.** Gmail shows the sending Google account's profile photo beside the sender's name, and nothing in the email can change it. Set that account's photo to the Hult Prize mark.
- **Testing.** Run `sendFollowUpTest()` from the Apps Script editor. It sends four previews for the latest event to the first address in `ATTENDANCE_TEST_EMAILS` only: the card and the letter, each with and without the optional-updates section. Nothing is queued, and it works while the script is live.
- **A missed send.** Run `sendFollowUpsForLatestEvent()`. For the most recent event that has ended, it queues every follow-up that is already due and skips anyone who already has one. It says when anything not yet due will be. The first 15 send immediately; maintenance sends the rest at 15 every five minutes. It works without `ATTENDANCE_FOLLOW_UP_MODE`, and it logs how much of today's MailApp quota is left: 100 recipients a day on a personal Gmail account, 1,500 on Google Workspace. Reminders and confirmations draw on the same quota. Retrying a failed follow-up from the dashboard also ignores the time window.
- **Delivery order.** Follow-ups are sent after any other waiting email, so a wave of them never holds up someone's sign-in link or confirmation.
- **Classic Outlook.** It ignores `max-width`, so the email wraps its content in a 560px table that only Outlook sees. It shows a lead's picture above the words rather than beside them, so the words get the box's full width and a hyphenated name never breaks at its hyphen, even with Windows display scaling.
